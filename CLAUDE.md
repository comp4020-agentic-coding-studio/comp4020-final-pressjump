# CLAUDE.md: the harness for Bench

Bench is a shared drafting table: a few people, one sheet, millimetres, a part
at the end. `README.md` is the argument for what good means here. This file is
the rules that argument turns into. `spec/` is the part of it a machine checks.
When the three disagree, the README wins and the other two get fixed.

## The four promises, and what each one forbids

1. **The numbers are true.**
   - Every coordinate is millimetres, stored as a number rounded to 0.001 mm.
     There is no other unit anywhere in the model, the protocol or an export.
     Pixels exist only in the client's view transform.
   - Every geometric field of every shape can be typed in the properties panel.
     A shape kind that can only be dragged does not ship.
   - Exports are generated by the server from the stored shapes, not from
     what a client happens to be displaying. SVG carries `width`/`height` in
     `mm`; DXF sets `$INSUNITS` to 4 and flips y so the part is not mirrored.
   - Geometry is validated in one place, `shared/geometry.ts`, and the server
     runs it on every shape it accepts. The client running it as well is a
     courtesy, never the check.

2. **Nobody's work is overwritten without them seeing it.**
   - The server is the only authority on what the sheet holds. A client's
     state is a view of it, plus edits it has sent and not had answered.
   - Every update and delete carries the version it was made against. The
     server refuses it if the version is not the current one. Never "fix" a
     refused edit by dropping the version check or retrying with a fresh
     version; that is exactly the silent overwrite this app exists to prevent.
   - A shape held by one person cannot be changed by another. Holds die with
     the connection that took them and after two minutes of silence.
   - A refusal is always shown to the person whose edit was refused, in words,
     with who caused it where that is known. A refusal that only reverts the
     shape reads as a bug.
   - Undo only undoes your own change, and only if the shape is still what you
     left it as. Otherwise it says why it will not.
   - While disconnected, editing is off and the page says so. Edits are never
     queued offline to be replayed over whatever happened meanwhile.

3. **You can see the other people.**
   - Every connected person has a name and a colour, and both show on their
     cursor, on anything they hold and in the people list.
   - What someone is drawing or dragging is visible to others before it is
     committed. It is not persisted.
   - Presence traffic is batched by the server (one message per client per
     50 ms at most), because a full room is the case this is designed for.

4. **It stays.**
   - A change is written to SQLite before it is broadcast. Never reorder
     these.
   - The database lives under `DATA_DIR` (`/data` on Fly, the only volume).
     Nothing that has to survive a restart lives anywhere else.

## What not to build

No accounts, no chat, no comments, no history browser, no layers, no 3D, no
constraint solver, no drawing deletion. If a change seems to need one of these,
stop and say so instead of building it; the README says why each was left out.

## Rules for the platform

- **Node 24 runs the TypeScript directly.** Only erasable syntax: no `enum`,
  no `namespace`, no constructor parameter properties. `erasableSyntaxOnly` in
  `tsconfig.json` enforces it. Relative imports name the `.ts` file.
- **No native dependencies.** The image is `node:24-alpine` on a 256 MB
  machine. SQLite is `node:sqlite`, which ships with Node.
- **Everything ships in the image.** No CDN scripts, no remote fonts, no
  runtime fetches to anything but this server.
- **The client is bundled by esbuild into `public/build/`**, which is
  generated and never edited or committed.
- **Bounded everything.** Messages are capped at 16 KB, shapes per sheet at
  5000, messages per connection per second at 120. A limit that is hit is
  answered with a refusal, not a crash.
- **`/readme/` renders `README.md` on the server**, so the headings are in the
  HTML before any script runs. Images in the README live in `docs/` and are
  linked relatively.
- **Works at phone width.** 390 px, no horizontal page scroll, every tool
  reachable, two-finger pan and zoom. Check it on a real phone before saying it
  works on one.

## Rules for working

- **`pnpm check` is green before every commit.** It runs against a running
  server: `pnpm build && pnpm start` in one terminal, `pnpm check` in another.
- **A new spec test first catches a deliberate bug.** Break what it forbids,
  watch it fail, put it back. A test that has only ever been green has not been
  shown to test anything.
- **Restarts are checked by restarting.** The spec runs against a server that
  stays up, so it cannot see a restart. After any change to `server/db.ts` or
  to the order of writes in `server/room.ts`: draw something, kill the server
  process (not Ctrl+C, which closes the database cleanly), start it again and
  open the sheet. It has to be there.
- **Two browsers, before saying a change to the editor works.** One desktop
  window and one at phone size with touch, as two people, doing the thing the
  change touched. The marker tests it that way, so that is the proof.
- **A class names one kind of thing.** The hold tag and the cursor name tag
  once shared `.hold-label`, so "is anything held?" was true whenever anyone's
  cursor was on screen. Overlay elements get a class of their own.
- **Corrections land here or in `spec/`.** When the agent gets something wrong
  in a way that could happen again, the fix is a rule in this file or a test,
  not just a retry.
- **Commit as the work lands, in the order it happened.** The history is read
  as evidence.
- **Never push or deploy without being asked.**
